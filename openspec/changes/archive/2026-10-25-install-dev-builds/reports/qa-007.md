## Findings

### QA-350: Rollback of a never-selected operation completes but exits 1 with a misleading "record disappeared" error

- Severity: warning
- Related task / requirement: 4.1 (Switch/Rollback recovery), design decision 4
- Location: `scripts/install-dev.ps1` finally at about line 1043 (`Remove-OwnedCoordinationRecords` when neither `selectionMutated` nor `monitoringMutationStarted`) versus the post-restart record check at about line 1062 (`throw 'Operation coordination record disappeared; preserving recovery state.'`), reviewed at `b74a12b` plus the dirty tree (identity above). The `never-selected` route is at about line 968.
- Expected / actual: A Rollback that recovers an operation whose pointer was never written (states `prepared`, `original-stopped`, `ready-to-select`) should finish with exit 0 and the normal result object. Actual: the original tray is restarted, the manifest reaches `running-original`, the records are removed, the selection is unchanged (the recovery is correct), but the command exits 1 with "Operation coordination record disappeared; preserving recovery state." because the `finally` already removed the records. The same occurs after a post-gate Switch drift refusal once the drift is undone, and in the marker-negatives positive control.
- Reproduction: `qa-007-native.ps1 -Cases rollback-never-selected` (Preflight, start Switch with a barrier dir, kill the installer at `switch-before-selection`, then `Rollback` of the same manifest).
- Evidence: [never-selected results](../evidence/qa-007-native-never-selected-results.json) (`exitCode 1`, `manifestState running-original`, `originalTrayRunning true`, `recordsRemoved true`, `selectionOriginal true`); follow-up rows in [post-gate Switch results](../evidence/qa-007-native-postgate-switch-results.json) and the `control` row of [marker results](../evidence/qa-007-native-marker-results.json). The suite has no test for Rollback from the `never-selected` route. Applies to both clients (shared path).
- Recommended correction: let the final record-ownership check treat records already removed by the no-mutation `finally` as complete for this route (or skip the second removal and check), and add a script test for a Rollback after an interrupted Switch before the pointer write that asserts exit 0, `running-original` and no records.
- Relationship: new; not a repeat of ANALYSIS-200 or ANALYSIS-201. It does not weaken the verified refusals.
