## Findings

### QA-150: a tray started during Switch's open launcher-gate phase survives selection change

- Severity: warning
- Related task / requirement: 4.1 unexpected-owner scenario; 4.3 hook continuity; task 6.1 Switch; added hook-maintenance requirement.
- Location: `scripts/install-dev.ps1:301`, `:323`, `:334–336` at target `diff=5b2efc8567ad`.
- Expected / actual: Switch must refuse and report a tray owner that differs from Preflight before changing `current.json`. Actual: it stops/verifies the Preflight tray at the start, releases the launcher gate for slow work, and checks only that `current.json` still has its original hash before writing the candidate. It does not exclude or recheck a tray that starts during that interval. In the disposable reproduction, selection changed to 0.1.9002 while the tray that had just appeared continued running 0.1.8.
- Reproduction: run [the QA harness](../evidence/qa-003-owner-race.ps1). It creates a fresh installation and data directory under `artifacts/qa-003-owner-race`, performs Preflight and starts Switch with `-TestBarrierDirectory`, starts the original 0.1.8 tray after the `.entered` marker appears, waits for `tray.json`, then releases the barrier. Observe Switch exit code 0, candidate selection, `trayRestarted:false`, and the old tray's `tray.json`/PID. Exact results are in [QA-150 evidence](../evidence/qa-003-owner-race-result.md).
- Evidence: generated run used the real stable launcher and tray from the archived disposable 0.1.8 payload and marked dev package 0.1.9002. No user path or process was used. The harness cleaned up its tray; `Get-Process -Id 39376` returned no process afterward.
- Recommended correction: coordinate tray start with the already supported restart-marker protocol across the open phase, or implement an equivalent safe handshake that works with the installed 0.1.8 launcher. Refuse unexpected owner changes before selection, retain the update gate and hook availability, and clean up/resume the handshake safely on success, refusal and recovery. Add a regression that starts a tray while Switch is blocked and verifies it cannot remain on the old selection after release.
- Relationship: new; raised independently of the code-analyzer's source observation.

## Assessment and limitations

QA-150 is blocking for release acceptance: a concurrent tray can remain on 0.1.8 after Switch selects 0.1.9002. I notified the orchestrator and recommend a consolidated fix round before native-cycle and AOT benchmark acceptance.

The work-machine cause remains unverified. Historical 0.1.8 timing evidence and this separately reproduced installer owner race describe plausible mechanisms; neither test was an authenticated work-machine hook trial. No active user tray/session or provider settings were changed. The working-tree target and unrelated staged files remained unchanged.
