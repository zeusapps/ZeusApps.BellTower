## Findings

### QA-1700: Git test fixture can run against the real repository (isolation leak)

- Severity: warning
- Related task / requirement: test hygiene; DEV-023 test runs
- Location: tests/BellTower.Tests/Testing/GitHelper.cs:8-19; tests/BellTower.Tests/Testing/WorktreeFamily.cs:19-29; tests/BellTower.Tests/Testing/TestWorkspace.cs:19-20
- Expected / actual: fixture git commands should only ever touch the disposable repository. Actual: `GitHelper.Run` inherits the full parent environment and never clears `GIT_DIR`, `GIT_WORK_TREE` or `GIT_INDEX_FILE`. It never sets `GIT_CEILING_DIRECTORIES` and never checks where git resolved. `WorktreeFamily.Create` only asserts that `git init` exits 0 and then commits with `--allow-empty` (`user.name=Test`, `test@example.invalid`, message `initial`). The workspace root is `<repo>/artifacts/unit-tests/<guid>`, inside the real repository, so any condition that makes git resolve upward or via env lands on the real repo. `WorktreeFamily.Commit` is also public static and takes any directory.
- Reproduction (safe, on a throwaway repo under the scratchpad, never the real repo): create repo R with one commit and a subdirectory `artifacts/t/D360`. Set `GIT_DIR=R/.git` and `GIT_WORK_TREE=R`. Run `git -C D360 init --initial-branch main`. It exits 0 with only the warning "re-init: ignored --initial-branch=main" and creates no `.git` in D360, so the Assert passes. Then run `git -C D360 -c user.name=Test -c user.email=test@example.invalid commit --allow-empty -m initial`. It exits 0 and R's log gains `Test <test@example.invalid> initial`, which is exactly the observed symptom. With only `GIT_DIR` set the commit failed (not a work tree), so the exact env that triggered it is unconfirmed; the worktree-add and later steps would likewise act on the real repo. In my runs the ambient env had no `GIT_DIR` or `GIT_WORK_TREE`, and 1209 tests produced no real-repo commit, so the leak is intermittent and environment-dependent (likely git hooks or tool wrappers exporting `GIT_*`, or a run launched from such a context). This is a demonstrated vector, not a proven root cause for the incident.
- Evidence: reproduction above; `ReviewIdentityScriptTests` already isolates its git calls (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_SYSTEM`), but the shared `GitHelper` used by WorktreeFamily, CheckoutResolutionTests, WorkPolicyTests and others does not. The `Git(...)` helpers in IdentityPrecedenceTests.cs:81 and GitTests.cs:44,56 are separate and should be checked for the same exposure.
- Recommended correction: (1) in `GitHelper.Run` remove `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`, `GIT_NAMESPACE` from the child environment, and set `GIT_CEILING_DIRECTORIES` to the parent of the test root (or `GIT_CONFIG_GLOBAL`/`NOSYSTEM` as in the script tests). (2) After `git init` in `WorktreeFamily.Create`, assert that `git rev-parse --show-toplevel` equals the family directory and that `<dir>/.git` exists, before any commit; refuse to commit otherwise. (3) Have `Commit` do the same guard, or make it private. (4) Move the test root outside the repository (for example under the system temp directory) or add a repository-rooted guard that fails when the root resolves inside the real repo. (5) Optionally add a unit test that sets `GIT_DIR` to a decoy repo and proves the fixture does not alter it. Apply the same environment scrub to the other test git helpers.
- Relationship: new
