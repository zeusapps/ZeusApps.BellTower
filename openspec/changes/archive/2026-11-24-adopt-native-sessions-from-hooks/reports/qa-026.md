## Findings

### QA-2601: Real Codex install layouts that would put a `codex.exe` directly above the backend are unverified

- Severity: suggestion (information; not a defect in the change)
- Related task / requirement: 2.5; QA-2500 fix
- Location: `src/BellTower/Hosts/AttachmentCapture.cs` (`parentIsAgent`); `src/BellTower/Sessions/CodexRuntimeHost.cs` `RunAsync`
- Expected / actual: the rejection is fail-closed. If a real install had manager -> `codex.exe` wrapper -> `codex.exe app-server`, the owned backend would end shared (no host, no name write, no pump). The three shapes `CodexRuntimeHost` produces never have this form, and the installed npm package spawns its single vendored `codex.exe` straight from node. Other versions and install types are unknown. That shape was already shared at `e0a69e6`, so there is no new loss.
- Reproduction: none (no defect). Existing row `("codex","app-server","codex","valid")` shows the shared result.
- Evidence: source reading and the file listing; no provider launched.
- Recommended correction: none required. If a wrapper layout appears, the symptom is a managed `Start-Codex` conversation in the shared shape; capture the process tree then.
- Relationship: related to QA-2500.
