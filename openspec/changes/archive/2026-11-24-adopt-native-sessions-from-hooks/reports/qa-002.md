## Findings

### QA-100: Partial desktop removal clears the shared VS Code tab title

- Severity: warning
- Related task / requirement: partial task 5.1 setup ownership; selected-provider removal must retain settings still consumed by another installed provider.
- Location: `src/BellTower/Setup/TerminalProfilesEditor.cs:70` at reviewed identity `a69392e9ae6734b7f229d9266ebe4a3144ef49a4`.
- Expected / actual: Removing one selected provider while another provider still owns desktop profiles should preserve `terminal.integrated.tabs.title` for the remaining profiles. `VsCode` currently passes `null` whenever `remove` is true, so the setting is removed on partial provider cleanup.
- Reproduction: In a disposable fixture home, apply desktop setup for both providers, then apply generic removal for Claude only (`setup --clients claude --remove --apply`, with isolated `--home` and `--data-dir`). Inspect VS Code `settings.json`: Codex profiles remain owned, but the managed tab-title setting is removed.
- Evidence: Source inspection of `TerminalProfilesEditor.VsCode` shows the unconditional removal at line 70; `DesktopSetup.Plan` invokes it for the selected provider during generic removal. The passing tests do not assert retention of this setting after partial generic desktop removal. No product setup was run in this review.
- Recommended correction: Retain or release the tab-title setting according to whether any remaining desktop profile still consumes it, using the existing ownership record and reversible settings policy.
- Relationship: New regression found during QA-002; independently matches analyzer recheck ANALYSIS-100.
