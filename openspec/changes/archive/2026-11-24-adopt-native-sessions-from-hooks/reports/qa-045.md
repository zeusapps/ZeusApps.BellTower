- Expected / actual: Expected on by default with a tray opt-out. The "Adopted direct sessions" bullet says the title and background apply "only when the tray setting **Title and color native sessions** is on" and "The setting is off by default and applies to running sessions without a restart."
- Reproduction: `grep -n "off by default" docs/compatibility.md`

### QA-4502: nested-client test no longer proves, by its resolver assertion, that a nested client avoids the managed launch's presentation

- Severity: suggestion
- Related task / requirement: 4.3; nested-client test in `tests/BellTower.Tests/Providers/NativeAdoptionReconcileTests.cs` (line ~52)
- Location: `NativeAdoptionReconcileTests.cs`, `ANestedClientThatInheritedAManagedIdentifierKeepsItsOwnIdentityAndNoLaunchPresentation`
- Expected / actual: With the setting now off only by explicit test setup, `Resolve(...)` returns null for any non-managed attachment, so that assertion on its own can no longer distinguish "never inherits the launch presentation" from "setting off". The preceding assertions (`own.ManagedTitle` and `own.ManagedBackground` false, own id and process, own `Host.Shell` rule, identity name and change not equal to the parent's) still prove that the nested session did not inherit managed flags or identity text, and a regression that copied the managed flags would make `Resolve` non-null even with the setting off. So the intent is kept. The new setup is adequate, with a gap: nothing checks that, with the setting on, the nested session's title is its own and not "Parent task".
- Reproduction: read the test; I did not run a mutant against it.
- Evidence: source inspection only.
- Recommended correction: Optionally add a second assertion after switching the setting back on that the desired title or background derived for the nested session does not contain the parent's name and that the original launch record is unchanged.
- Relationship: none

Other changed tests: the pump test, the off test in `NativePresentationTests`, and `TerminalTabSelectionTests` only gained an explicit `false`. Assertions and intent are preserved.
