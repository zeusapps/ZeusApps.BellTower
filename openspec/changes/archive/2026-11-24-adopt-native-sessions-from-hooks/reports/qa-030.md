## Findings

### QA-3000: The real-ioctl-unavailable path of `CodexSharedPeer.PeerPid` is pinned only indirectly

- Severity: suggestion
- Related task / requirement: 3.1 (fail-closed provenance, "no silent fallback")
- Location: `src/BellTower/Providers/CodexSharedPeer.cs:17-30`; `tests/BellTower.Tests/Providers/CodexTransportTests.cs:128-136`
- Expected / actual: The `PeerUnavailable` test injects a `peerOf` that returns null. It proves that a null peer fails closed with `PeerUnavailable`, but it does not exercise the real `PeerPid` catch branch or the "PID not readable" branch (`ProcessProbe.Identify` returning null). Mutant 4 (real ioctl made unavailable) fails 19 tests, so the direct-ioctl dependency is covered, but the failure is not asserted as `PeerUnavailable` anywhere for the real code path: an ioctl that threw an unexpected exception type would escape as a raw exception rather than a `CodexTransportFailure`. By source inspection and the mutant run; no defect observed.
- Reproduction: Mutant 4 as described above (guarded throw before `IOControl`); inspect which test asserts `PeerUnavailable` (one, injected).
- Evidence: this report, mutant row.
- Recommended correction: optional. Add a unit test that calls `CodexSharedPeer.PeerPid` on a never-connected or disposed socket and asserts null, and one for an unreadable PID (for example a nonexistent PID) mapping to `PeerUnavailable`.
- Relationship: new

## Assessment and limitations

Acceptance covered for the assigned recheck: build, targeted 35/35, full suite 1472/1472, ten repeated `CodexTransportTests` runs with no flakiness and no leaked child `pwsh` process or temp artifact, four independent mutants killed by named tests (the ioctl mutant needed a second attempt because the first did not compile), and a no-quota native confirmation on Codex 0.166.0 with peer-derived identity, an extra-probe effect check, and `Replaced == True` through a single access instance. The extra connect-and-close per request had no observable effect on the private backend.

Limitations: the `SIO_AF_UNIX_GETPEERPID` ioctl still has only secondary documentation and measured behavior on this Windows 11 build; an elevated or otherwise unreadable peer was not natively exercised; backend-side debug logging of the probe connections was not enabled, so "no visible effect" means no error, crash, change of service or new log line. The tests depend on `pwsh` on PATH, which the CI runner provides.
