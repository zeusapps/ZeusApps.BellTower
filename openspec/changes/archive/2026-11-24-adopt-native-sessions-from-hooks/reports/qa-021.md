## Findings

### QA-2100: Two guards of the shared reducer are correct but not pinned by any test

- Severity: warning
- Related task / requirement: 2.3, 2.4 (an `EndedAt` set by an older tray must stay ended; untrusted future observations), design decision 2 freshness rules
- Location: `src/BellTower/Core/AttachmentHealth.cs` line 15 (`attachment.EndedAt is null &&`); `src/BellTower/Core/ConversationLifecycle.cs` line 161 (`active.ObservedAt <= now + ClockSkew`) and lines 161-162 (clamp to now); `tests/BellTower.Tests/Providers/ConversationLifecycleTests.cs` lines 405-415 (`StaleRuntimeEvidenceIsNotWork`)
- Expected / actual: each stated rule has a test that fails when it is broken. Actual:
  - Removing the `EndedAt is null` gate (F9) leaves all 76 tests in the four suites passing, yet a shared record that an older tray ended (it ends a record on a dead `Host.Shell`, which is the reason for the 4.2 constraint) would be reduced back to `unverified`/`unavailable` instead of staying `confirmed-ended`. Scratch test `EndedSharedStaysEnded` passes on the real code and fails under F9.
  - Accepting a future runtime observation (F1) also survives: `StaleRuntimeEvidenceIsNotWork` ends with a future-observation fixture line (line 414) that has no assertion. Scratch test `FutureRuntimeFactIsNotWork` (Active fact one hour ahead must stay `unavailable`) passes on the real code and fails under F1.
  - Removing the clamp to now (F14) survives; it only lets `UnverifiedSince` land up to 30 s in the future, so it is minor.
- Reproduction: copy the repository to a scratch directory, apply the single-expression mutation named above, run `dotnet test --filter ConversationLifecycleTests|AttachmentHealthTests|AttachmentEvidenceTests|StorageTests`; all pass. Add the two scratch tests quoted in this section to see them fail.
- Evidence: scratch runs described in the checks table (the scratch copy was deleted afterwards).
- Recommended correction: add a test with an `EndedAt`-set shared record expecting `confirmed-ended` and `EndedAt` preserved, and finish `StaleRuntimeEvidenceIsNotWork` with the missing assertion for the future observation (and, optionally, for the clamp).
- Relationship: new; same class as QA-2002, which is otherwise fixed
