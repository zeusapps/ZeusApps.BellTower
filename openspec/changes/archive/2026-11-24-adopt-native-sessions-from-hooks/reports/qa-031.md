## Findings

### QA-3100: origin of DEV-036's denied provider CONNECT not isolated and not reproduced

- Severity: suggestion
- Related task / requirement: 3.2 native check; evidence/implementation-036.md "Native check"
- Location: `evidence/implementation-036.md` (native check paragraph)
- Expected / actual: the developer evidence leaves open whether the single denied CONNECT came from backend start or from `thread/start`. In this independent run (same Codex version, dummy key, same proxy settings, same product open/read/name path, plus a real restart) the loopback proxy recorded no request at all: not at backend start (up to 10 s), not after `thread/start`, not after reads, not after a restart.
- Reproduction: the sequence above.
- Evidence: proxy log size 0 bytes at seven sample points. The attempt in DEV-036 may have come from something the harness did that I did not (a different harness call, a model-list or plugin refresh triggered later in time, or the longer lifetime of that backend), so I cannot attribute it. Neither backend start nor `thread/start` alone caused it here.
- Recommended correction: none required for acceptance. In the evidence, record that the origin is undetermined and that two independent runs (QA-030 and QA-031) saw no egress attempt; if it recurs, sample the log between harness steps with timestamps.
- Relationship: new

### QA-3101: fork and delegated threads are refused on a shared backend until a fork hook probe exists

- Severity: suggestion
- Related task / requirement: 3.2 hook session to thread proof; design decision 4; parity policy (exceptions need evidence)
- Location: `src/BellTower/Providers/CodexThreadIdentity.cs:36-43`
- Expected / actual: the policy treats a missing implementation or investigation as unfinished work. The code correctly refuses these cases and the developer states it is unfinished evidence, not a restriction. A user forking a conversation in a shared-backend session will see `unavailable: conversation is not proven to match the runtime thread`, which is honest, but there is no task in tasks.md that tracks the fork hook probe.
- Reproduction: tests `AThreadThatIsNotProvenToBeTheHookConversationIsRefusedOnASharedBackend` (fork, parent, agent rows).
- Evidence: the cases pass and mutant `fork` was killed.
- Recommended correction: add or reference a task and a capability-matrix row for the fork hook probe so the refusal does not become permanent by omission.
- Relationship: new
