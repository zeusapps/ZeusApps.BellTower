# Timeout fixture evidence: 2026-10-23

These trials use private configuration and disposable repositories under `artifacts/hook-ingress`. No personal transcript or configuration was read or changed. Credentials were dummy fixture values. Claude's model endpoint was an unreachable loopback address; Codex used a loopback fake model endpoint returning a fixed two-token fixture response. No authenticated model trial is claimed. Only disposable probe processes were stopped.

## Claude 2.1.306, SDK CLI

Evidence root: `artifacts/hook-ingress/timeout-f76c115647b94842849ab5b5944643bb`.

An explicit settings file installed SessionStart and UserPromptSubmit command hooks, each with a one-second timeout and a three-second fixture sleep. The client used `--setting-sources ''`, no tools, an empty strict MCP configuration, a custom `pm` main agent and `dontAsk` permissions. Nonessential traffic was disabled and the API endpoint pointed to loopback port 9. The disposable client was stopped after its connection retries; hooks and their transcript records had already completed.

Two actual records have root `type: attachment` with nested `attachment.type: hook_cancelled`, boolean `timedOut: true`, integer `timeoutMs: 1000`, durations 3790/3781 ms and root timestamps 11:09:48.914Z / 11:09:52.770Z. The custom-main UserPromptSubmit input has `agent_type: pm` and no `agent_id`.

The checked-in minimal fixtures preserve these field names, types and timestamps. Commands, IDs, paths, user text and unrelated fields are omitted/redacted. The separate nine-case provider inventory remains synthetic documented-contract input.

## Codex 0.164.0, local exec and terminal CLI

The timeout trial at `artifacts/hook-ingress/codex-timeout-afd14c075e7c4608977c94927b8438be` installed a reviewed SessionStart command in a private CODEX_HOME. It wrote a start marker, slept three seconds, then would write a completion marker. With a one-second budget, the start marker existed, completion did not, the invocation took 1817 ms and the client exited zero. The matching five-second control at `codex-timeout-68624c7d3d0b4b79bf422eebed66e73b` completed the marker in 4788 ms. Each contacted only the loopback fake endpoint once.

A native terminal-mode probe used a disposable pseudo-console, the same local provider and private trusted repository, `--no-daemon`, and the same one-second fixture. Evidence root: `artifacts/hook-ingress/codex-timeout-59c5ca594b68453a89aab20faf9de8d6`. The actual TUI displayed `Hook failed` and `hook timed out after 1s`, then the fixed fixture response. Only that terminal session was closed. Its transcript identifies source `cli`; exec identifies source `exec`.

All three retained transcripts contain 14 records. Inspection of the complete structured records found no hook-result/timeout record, despite verified hook execution and the terminal's explicit timeout warning. The two minimal Codex fixtures contain the actual session metadata and completion timestamps from the timeout runs; other records are omitted. They deliberately do not fabricate a hook timeout entry. Full transcripts remain at the isolated evidence roots.

### Narrow restriction and shared fallback

Exact unavailable operation: infer complete retrospective hook-timeout counts from the chat JSONL generated by Codex 0.164.0 local exec or the tested local no-daemon terminal CLI. At least the tested SessionStart timeout status is not persisted there, so a complete count cannot be reconstructed. This does not restrict fast capture, setup, lifecycle reduction, identity, colors, attention or general capture diagnostics. No claim is made that every other hook type uses identical persistence.

Doctor recognizes that version/source pair and returns a null timeout count plus `timeout-records-unavailable-in-verified-cli-mode`, with the shared capture-health/native-hook-status fallback. It never reports zero as proof that no timeout happened. Other version/source pairs remain explicitly unverified. Regression tests cover both recorded modes and unverified input. This exception is limited to this retrospective transcript surface; it does not excuse missing capture implementation in either provider.

The one-off hook-trust override was limited to fixture sources vetted by this harness; production provider trust was unchanged. This automation mechanism is documented in the [official Codex hook reference](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks). That reference also states that transcript formats are not a stable hook interface. Claude's [official hook reference](https://code.claude.com/docs/en/hooks) supplies the common input contract; the retained capture supplies the otherwise undocumented timeout JSONL shape.
