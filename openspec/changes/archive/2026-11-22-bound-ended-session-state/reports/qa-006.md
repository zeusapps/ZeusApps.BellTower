## Findings

### QA-500: A quoted rooted path whose closing quote is followed by `]`, `?`, `"`, `>`, `}`, `-` or `/` is not matched and the last word of a name with a space leaks

- Severity: warning
- Related task / requirement: 2.1; spec sanitized reason; design decision 4 (a rooted quoted segment is masked through the last closing quote on its line)
- Location: `src/BellTower/IO/RefreshHealth.cs:228` (`Quoted`, lookahead `(?=[\s.,;:)!]|\z)`), at 5e95554
- Expected / actual: the structural rule should leave no fragment of a rooted quoted path. A closing quote followed by one of the characters that is not in the terminator set leaves `Quoted` unmatched, so only the unquoted rule masks the path, and it stops at the first space: `Denied 'C:\a\My Repo'?` gives `Denied '<path> Repo'?`, `Denied ['C:\a\My Repo']` gives `Denied ['<path> Repo']`, and `Denied "'C:\a\My Repo'" now` gives `Denied "'<path> Repo'" now`. The same applies to a profile path (`'C:\Users\Jo Doe\x y'/z q` gives `Denied '<path> q`) and to `]`, `}`, `>`, `"`, `-`. A message wrapped in brackets, JSON or a quoted aggregate form therefore reproduces the ANALYSIS-400 class of leak.
- Reproduction: scratch console project outside the repo (reference the Release `bell-tower.dll`), `RefreshHealth.Describe(new IOException(@"Denied 'C:\a\My Repo']"), @"C:\Data\BT", @"C:\Users\Jo Doe", "Jo Doe")`; output `IOException: Denied '<path> Repo']`.
- Evidence: the probe output described above (18 inputs, 12 of them in this class leak; the other 6 passed).
- Recommended correction: widen the closing-quote lookahead from an enumerated set to any character that is not a letter or digit (and not the apostrophe itself), for example `(?![\p{L}\p{N}])`, or add `]`, `}`, `?`, `"`, `>`, `-`, `/`. Add the cases to the quoted-path theory. The accepted over-masking in decision 4 still applies.
- Relationship: same class as ANALYSIS-300 and ANALYSIS-400 (quoted-path final-name leak); distinct trigger (closing delimiter). Not covered by the DEV-006 cases.

## Assessment and limitations

- DEV-006's structural rule fixes the reported ANALYSIS-300 and ANALYSIS-400 inputs and the broad matrix of apostrophes, spaces, drive, UNC, Unix, profile (space and apostrophe in the user name), data-directory and multi-path inputs. The cost bound is much better than before (worst 4 ms). The sanitizer does not mask ordinary non-path messages beyond the accepted over-masking between a rooted quote and the last close on its line.
- One blocking finding remains (QA-500): the closing-quote terminator set is enumerated, so other closers fall back to the unquoted rule and leak the last word of a name with a space.
- Known, not blocking: unquoted paths with a space in the final name (`<path> Repo`, `<path> q.txt`) are not delimitable and keep the trailing words, as before DEV-006; relative quoted paths (`'.\My Repo\x y'`, `'~/My Repo/x'`) are not masked because they have no root. Neither is in the ANALYSIS-300/400 scope. If the user wants either closed, it needs a decision.
- Not performed: any live tray, installed native or real data directory check (none needed for this scope). The scratch project under the scratchpad is outside the repository; no source or ledger edits were made. The full-suite load-only failures passed in isolation (2 of 2).
