## Findings

### QA-080: Task 3.4 requires `update-acceptance.ps1 -BaselineArchive` against a fixture-version candidate, which the script cannot do

- Severity: warning
- Related task / requirement: 3.4, 2.1; ANALYSIS-060 fix
- Location: `openspec/changes/validate-next-release-field-acceptance/tasks.md:25` (task 3.4); `scripts/update-acceptance.ps1:6,13-15` at `02d4f56`
- Expected / actual: expected, 3.4 can run "`scripts/update-acceptance.ps1` (including `-BaselineArchive` with the real 0.1.9 archive against the fixture-version candidate)" before 4.4. Actual: the script always builds its candidate itself with `./scripts/package.ps1` (no `-FixtureVersion`) and takes `$version` from `Directory.Build.props`. Before 4.4 that is 0.1.9, the same as the real baseline. `Smoke` then fails `Assert(original != offer.Version, "Acceptance requires distinct compiled versions.")` (`Program.cs:52`). The script has no parameter for a pre-built or fixture candidate. A literal run of 3.4 therefore fails, or runs with a mislabeled candidate.
- Reproduction: read `update-acceptance.ps1` and trace with `Directory.Build.props` at 0.1.9 and `-BaselineArchive` set to the real 0.1.9 archive. (Not executed, because it would build and package from source and was out of scope.)
- Evidence: source inspection only. The same step works after 4.4 because the declared version is then 0.1.11.
- Recommended correction: the orchestrator should reword 3.4 to one of: run the real-baseline update acceptance before 4.4 by invoking `dotnet run --project tools/BellTower.Smoke -c Release --no-build -- <real 0.1.9 archive> <fixture-version 0.1.11 candidate zip>` (the Smoke only needs the zip and its adjacent `.release.json`), or have the developer add an optional candidate or fixture-version parameter to `update-acceptance.ps1` as a task. State that `update-acceptance.ps1 -BaselineArchive` itself is run only at 4.4. Keep the fixture-version label on the pre-4.4 evidence.
- Relationship: residual of ANALYSIS-060
