## Findings

### QA-260: Claude null-process checks fail reproducibly when the harness runs under a live `claude.exe` host (run-environment dependent)

- Severity: warning (the harness verdict is not reproducible; the product cause is unproven)
- Related task / requirement: 2.4 null-process (F4), ANALYSIS-241, ANALYSIS-242
- Location: `tools/BellTower.FieldAcceptance/Scenarios/FaultGroupRun.cs` (`InjectNullProcessStartup`, `rollback/liveness`), `src/BellTower/Hosts/AttachmentCapture.cs:67-69` (`Ancestors` walk takes the first `claude.exe` ancestor, up to 32 hops, `IO/ProcessTable.cs:21-40`)
- Expected / actual: expected 161/161 (developer, twice). Actual 151/161 in two separate runs started from Claude Code (once via Git Bash, once via the PowerShell tool). In every Claude-bearing group (Claude, mixed) four checks fail and the expected-failure ghostplain row reads differently: `candidate/null-process-startup` (ghost and heal read `verified-live`, not unverified), `candidate/null-process-unavailable` (ghost `verified-live`, activity `working`), `candidate/null-process-later-hooks/heal` (waits 0; the later hooks carry a native `claude-<pid>-...` id), `rollback/liveness`. `null-process-plain-startup/ghostplain` showed 1 attachment id and 1 wait instead of "fresh id per hook". Codex null-process checks passed.
- Reproduction: run `scripts/field-acceptance.ps1 -Scenario faults-and-rollback` from a Claude Code session whose host process is `claude.exe` (host PID was an ancestor of the harness through `cmd.exe` or `bash.exe`).
- Evidence: `artifacts/qa014/faults.txt`, `faults2.txt`. Developer's [harness-2.4](../evidence/harness-2.4.md) rows show the same checks passing (ghost unavailable). Hypothesis, not proven: the unidentified fake agent's hooks find the real host `claude.exe` in the ancestry (the harness does not sever or mask the real process tree), so the ghost is captured as live. The sandbox was removed after each run, so the ghost's attachment record could not be inspected.
- Recommended correction: make the null-process model independent of the host, for example by launching the harness with a parent chain that contains no provider-named image, or by having the check assert the ancestry it relies on (and fail loudly with the host image name). Then rerun in a Claude Code host. Developer should also state how its runs were launched.
- Relationship: ANALYSIS-241, ANALYSIS-242; not a repeat of QA-241.
