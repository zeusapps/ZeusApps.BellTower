## Findings

### QA-021: Fixed-sleep cache fixture is nondeterministic in the full suite

- Severity: warning
- Related task / requirement: 1.3; full regression acceptance for current-session microphone state
- Location: `tests/BellTower.Tests/Tray/AudioQueueTests.cs:569`
- Expected / actual: The test should wait until its first background probe has actually started before releasing it and asserting a second scan starts at the one-second freshness boundary. Under the full suite the ThreadPool delegate started late; the fixture saw only one probe call and failed its `calls == 2` assertion. The source state remained fail-closed while that query was pending. The exact test passed five isolated reruns and all 53 focused audio/config/diagnostics tests passed.
- Reproduction: Full suite produced `Failed: 1, Passed: 1044`; failure was expected call count 2, actual 1. Five serial runs of the isolated filter all passed.
- Evidence: Full run output plus five repeat summaries in this review; source returns Unknown while no completed fresh observation is available.
- Recommended correction: Add a test-only start signal set inside the first probe delegate and wait for that signal before starting the 800 ms freshness interval, then keep the first result's timestamp explicit. Rerun the full suite to obtain a stable pass.
- Relationship: New QA finding; related to but distinct from the corrected cache-logic issue ANALYSIS-004.
