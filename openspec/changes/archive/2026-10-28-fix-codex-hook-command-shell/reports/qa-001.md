## Findings

### QA-001: Subagent ToolStart can clear a foreground approval wait

- Severity: warning
- Related task / requirement: 4.2; shared foreground approval correlation and mixed-session isolation
- Location: `src/BellTower/Core/SessionReducer.cs:217` (wait-removal branches at lines 233–249 in the reviewed identity)
- Expected / actual: a subagent ToolStart must not resolve or remove a foreground permission wait. `ResumeForeground` processes a different operation and can remove a permission wait before checking `observation.IsMainThread` later in the method.
- Reproduction: create a main-thread permission wait tied to operation A, then apply a later `ToolStart` for operation B with `agent="subagent"` and `IsMainThread == false`. The different-operation resumption branch removes the wait before the main-thread guard.
- Evidence: source inspection of `ResumeForeground`; current subagent test at `tests/BellTower.Tests/Providers/CaptureTests.cs:338` only asserts thread classification. The full test suite could not connect to testhost, so this was not independently runtime-reproduced.
- Recommended correction: gate wait-resumption/removal on main-thread evidence, and add matched Claude/Codex reducer regressions covering a foreground wait followed by an unrelated subagent start, plus concurrent mixed-session coverage.
- Relationship: same issue as canonical `ANALYSIS-001`; do not duplicate the implementation fix.

### QA-004: Apostrophes in the temporary path invalidate the Codex probe TOML

- Severity: warning
- Related task / requirement: 2.2; setup probe must verify through Codex's real hook runner
- Location: `src/BellTower/Setup/ProviderHookProbe.cs:93` and `:122`
- Expected / actual: a valid temporary path containing an apostrophe must still produce valid isolated Codex configuration. The code doubles apostrophes inside a TOML literal string key, so Codex rejects the generated configuration when the temp path contains one.
- Reproduction: run the isolated Codex probe with its temporary root under a parent path containing an apostrophe; Codex rejects the resulting `[projects.'…']` key before the hook probe. The analyzer recorded a bounded installed-Codex reproduction; QA independently confirmed the escaping issue by source inspection.
- Evidence: `ProviderHookProbe.cs:93,122`; canonical `ANALYSIS-002`.
- Recommended correction: encode the project key using valid TOML string escaping (or avoid embedding the path in TOML), then add a probe regression for apostrophes in the temporary root.
- Relationship: same issue as canonical `ANALYSIS-002`; do not duplicate the implementation fix.

### QA-005: Malformed delivery marker can crash doctor reporting

- Severity: warning
- Related task / requirement: 3.2; delivery reporting must tolerate unreadable or unverified delivery state
- Location: `src/BellTower/Diagnostics/HookDeliveryReporter.cs:125-132`
- Expected / actual: a malformed or unexpected observed-marker shape should report delivery as unverified. A valid JSON array root, or an `at` property of a non-string kind, can make `TryGetProperty` or `TryGetDateTimeOffset` throw `InvalidOperationException`; the catch filter does not handle it, so doctor reporting can fail.
- Reproduction: place `[]` or `{"at":1}` in the isolated provider observed-marker path and request the delivery report. The analyzer recorded both bounded runtime reproductions; QA independently confirmed the unhandled JSON element-kind path by source inspection.
- Evidence: `HookDeliveryReporter.cs:125-132`; canonical `ANALYSIS-003`.
- Recommended correction: validate the root and `at` kinds before reading the timestamp, and treat unexpected JSON shapes as unverified; add regression tests for both inputs.
- Relationship: same issue as canonical `ANALYSIS-003`; do not duplicate the implementation fix.
