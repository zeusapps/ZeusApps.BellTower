## Assessment and limitations

The shared manual clock now controls both the native-source fixture timestamps and reminder playback validity time. The production seam defaults to UTC and is used only for reminder validity; ordinary alert checks keep their prior UTC path. Source timeout remains 80 ms and both freshness boundaries remain 500 ms. The full default suite passes all 1,089 tests, including the healthy, stale/future, mixed-provider, timeout, single-flight, and release-cleanup cases.

Only `TrayApplication.cs`, `ReminderFixtureDriver.cs`, `ReminderFixtureDriverTests.cs`, and `ReminderPlaybackTests.cs` differ from target-005. `WindowsUserIdleSourceTests.cs` is hash-identical to target-005; all other source/docs/config/policy and prior test paths are unchanged. Earlier full-suite failures remain historical evidence. This clean target-006 run does not establish their causes. Live native Windows APIs, installed tray operation, authenticated provider sessions, physical audio/input, and microphone behavior remain unperformed, not proven restrictions. No source/test/config/planning/ledger or personal production state was changed by QA.
