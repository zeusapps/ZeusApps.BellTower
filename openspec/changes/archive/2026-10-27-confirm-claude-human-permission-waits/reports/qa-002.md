## Findings

### QA-100: Dismissing the unverified chip hides the same request when a supported signal later confirms it

- Severity: warning
- Related task / requirement: 2.6; attention-notifications "Completion and permission grace" (an unverified chip "SHALL never be presented as a confirmed human wait"; design Decision 6: "replaced by the ordinary chip on confirmation")
- Location: `src/BellTower/Core/SessionReducer.cs` `Confirm` (keeps `wait.Episode`; reuses the episode the unverified chip belonged to) and `src/BellTower/Core/SessionState.cs` `RequiresAttention` (`Episode != AcknowledgedEpisode`), at the reviewed identity
- Expected / actual: after the user dismisses the "possibly waiting for approval" chip, a later supported confirmation of the same request (for example a Codex runtime that was unreachable and then reports `waitingOnApproval`) should surface the ordinary confirmed chip and its announcement, since the user dismissed an unverified guess, not a confirmed wait. Actual: the confirmed wait keeps the dismissed episode, so `RequiresAttention` stays false and `Collect` returns nothing; a real human wait is silent and invisible.
- Reproduction: probe X1 ([output](../evidence/qa-002-recheck-probe-output.txt), section X1): Codex session, provisional request at +1 s, `ConfirmationSignalUnavailable`, chip at +20 s, set `AcknowledgedEpisode = Episode` at +25 s, runtime-approval observation at +30 s. At +31 s and +40 s: Permission/Confirmed, due +35 s, `attn=False`, `ack==episode True`, `collect=0`.
- Evidence: [probe source](../evidence/qa-002-recheck-probe-source.cs.txt), section X1. Applies to either provider with the flag set (probe U shows the same shared path for Claude); in production only Codex sessions are flagged.
- Recommended correction: decide the intended behavior. If confirmation should override a dismissal of the unverified chip, give the confirmed wait a new episode (or clear the acknowledgement) when `Confirm` promotes a wait that was only chip-visible; add a regression test. If the dismissal is meant to stick, say so in the spec and design.
- Relationship: new

## Assessment and limitations

Acceptance covered by executed fixtures for both clients: README accuracy, the three ANALYSIS rechecks, tasks 2.6 and 2A.6 (apart from QA-100), and the earlier QA 001 functional probes, including the Claude AskUserQuestion field case and a mixed Claude plus Codex case (the latter from the suite). Build, 957 tests and format verify pass; identity unchanged.

Developer deviations (reported, not decided):

1. Transient `NativePermissionPending` still counts as active for presentation. Observed: reducer decisions agree across the causal and unordered paths (probe E); the flag only drives freshness, suppression and a bridge until the stored confirmation lands. Residual: presentation can briefly show attention from the flag before the stored state agrees, and some tests set the flag directly.
2. Restored Codex wait shows a confirmed chip immediately and silently. Verified only by pump tests; the policy start time suppresses the sound, but the chip appears without the 5 s grace after a restart.
3. Outdated ingress image does not mark question tools. Observed (probe L2): the question still stays one question with one announcement and no permission chip; the cost is a hidden ambiguous Permission wait until the question resolves. Doctor asks for "rerun setup". Not executed against a real packaged old image.
4. Claude with `permission_prompt` hooks disabled stays silent and undetected. By reading plus probe: only Codex is flagged, so such a Claude request gets no chip, sound or doctor warning (doctor reports "configured, not yet observed"). This is an accepted false negative the orchestrator should weigh against ANALYSIS-004.

Other observations (no finding raised in a recheck): two permissions old enough to be a held prompt's source leave both unconfirmed (H2), as specified, and a human wait with no later prompt never alerts for Claude. The overview row shows the "possibly waiting for approval" text with "(pending/dismissed)" before the 15 s grace has elapsed (`OverviewForm.cs:169`), while the strip chip waits the full 15 s; the spec describes the chip only.

Not performed: live auto-versus-human acceptance (3.4, 4.1), installed Claude Code or Codex, the real Codex pump and websocket, Codex `request_user_input_async`, the packaged update trial for ANALYSIS-001, other Claude permission modes. The probe project lives in the session scratchpad outside the repository; its source and output are retained as evidence. Findings and the ledger were not touched.
