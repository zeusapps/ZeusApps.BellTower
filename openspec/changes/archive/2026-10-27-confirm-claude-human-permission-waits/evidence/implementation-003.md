## Decisions and notes

1. Runtime attribution edge: when the confirmed wait resolves and a newer request is outstanding while the runtime still reports pending, that newer request is confirmed (the status cannot be attributed more finely). The 1 s pump cadence bounds the stale window.
2. `PromptObserved` is absent in older snapshots, so a Claude session restored from one shows the unverified chip until its first prompt; reset on attachment replacement. A Claude session whose first request exceeds 15 s without any prompt (including a genuine automatic approval) shows the chip by user decision (2.8).
3. The documented 6 s delay: Claude's documentation (not re-fetched here; value given in the assignment) and the 6.1 to 6.3 s captures.
4. Deferred and untouched: QA-002, QA-003, ANALYSIS-005, -006, -007 and the rest of ANALYSIS-004. Adjacent lines touched: `ConfirmationCoverageReporter` (new Claude fields only; raw `Confirmation` counting, QA-002, unchanged).
5. Rollback: an older tray ignores `restoredSince` and `promptObserved`; it would back-date nothing and treat the pump observation as a bare permission.
6. Not performed: live auto-versus-human acceptance, packaged update trial, real websocket pump, other Claude permission modes.
