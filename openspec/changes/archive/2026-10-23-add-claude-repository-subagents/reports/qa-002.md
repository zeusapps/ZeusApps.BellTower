## Findings

### QA-004: Reviewer format instruction cannot succeed on a dirty multi-change tree

- Severity: suggestion
- Related task / requirement: 2.1; design D7; assignment check "format verify scoped to the test file"
- Location: `.agents/roles/project-facts.md:11`
- Expected / actual: Expected: a reviewer can follow the facts file and get a meaningful result. Actual: "Format (reviewers): only `./scripts/format.ps1 -Verify`" runs against the whole solution, so it fails whenever any unrelated in-flight file is unformatted (it did here, three `src/` files, none in this change). The facts file gives no way to scope the check, so a reviewer must improvise (I used `dotnet format ... --include <file>`).
- Reproduction: `./scripts/format.ps1 -Verify` at the reviewed identity -> exit 1 with errors only in unrelated files.
- Evidence: output above; scoped run on the test file passes.
- Recommended correction: add one sentence to the reviewer format line, for example "if the whole-solution verify fails, report unrelated failures separately and verify your scope with `dotnet format ZeusApps.BellTower.slnx --no-restore --verify-no-changes --include <file>`", or extend `format.ps1 -Verify` with an optional `-Include`.
- Relationship: none
