## Findings

### QA-001: Beyond twelve live sessions, every extra session repeats the same color

- Severity: suggestion
- Related task / requirement: 2.1 thirteenth session, design decision 3, spec scenario "More live sessions than series colors"
- Location: `src/BellTower/Core/Palette.cs` `Palette.Allocate` (the fallback loop), at 605a513 plus the working tree
- Expected / actual: the rule is "largest minimum distance, ties by series order", which the code implements exactly and the spec allows. But once every series color is used once, each entry's minimum distance is 0, so the 13th, 14th and later sessions all take `Series[0]`; a 14th session then shares its color with two others while eleven colors have one user each. The tests only pin the 13th session (and the near-miss custom accent case), not the 14th. The result is spec-compliant, but it does not spread repeats, which cuts against the stated goal that repeated colors stay as different as the series allows.
- Reproduction: allocate with 12 series accents in use, then with those 12 plus `Series[0].Accent`; both return `Series[0]`.
- Evidence: reasoning from the code; `AFullSeriesTiesBreakInSeriesOrder` asserts only the first repeat. I did not add or run a probe, as I may not edit tests.
- Recommended correction: decide whether this is acceptable. If not, break equal-distance ties by the fewest current users of the entry (then series order), keep it deterministic, and add a 14th and 25th session test. Alternatively document that repeats beyond twelve all start at the first series color.
- Relationship: new

### QA-002: An identity written in the last hour counts as live even if its session ended and left the state

- Severity: suggestion
- Related task / requirement: 2.1, design decision 3 (ended sessions never count), spec scenario "Ended sessions do not block colors"
- Location: `src/BellTower/IO/IdentityStore.cs` `AllocatePalette`, the identity-file loop (`!state.Sessions.ContainsKey(saved.Key)`), at the reviewed identity
- Expected / actual: ended sessions must never block a color. Ended sessions stay in the state for up to 30 days, so the normal case is correct (and tested). The rule is only unsafe when an ended session is removed from the state early, for example the oldest-first budget trim in `StateSnapshotStore` or the ended-session cap, while its identity file was written within the last hour. Such a session would then reserve its color for the rest of that hour. The effect is a color skipped, never a duplicate, so it is minor. Separately, an identity created through `Get` for a session that never registers (for example a status-line or title read) also reserves a color for one hour.
- Reproduction: not executed; derived from `StateSnapshotStore.cs` lines 55 to 75 and `IdentityStore.cs` lines 124 to 130. Not covered by a test.
- Evidence: source inspection only, not a functional test.
- Recommended correction: accept and note it in the design (it is the safe direction), or add a test showing the one-hour reservation is intended. No code change required.
- Relationship: new
