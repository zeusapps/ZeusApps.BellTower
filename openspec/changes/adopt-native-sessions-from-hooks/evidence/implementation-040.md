## Changes
- ANALYSIS-2700 (decision: owned shutdown keeps terminating the backend's descendants): `docs/architecture.md` and the owner text of `ProcessStopAuthorityTests` now say that the stop marker only asks the owned manager to end; the manager terminates the backend it started together with its descendants (.NET's start-time check guards PID reuse); a failed or cancelled prepare terminates the manager's tree; only the tray holds observer connections; the scan pins the known terminating API call sites (a tripwire, not a proof of completeness).
- ANALYSIS-2704: the `CodexAccess.Owned` comment describes the mechanism (access records never stop anything; the runtime record plus a marker honored by its own manager is the only stop path).
- QA-3400 / ANALYSIS-2702: `RealRuntimeHostStopsOnlyTheBackendItStartedAndItsDescendants` uses a live `.cmd` stand-in backend (run through the PowerShell wrapper) that starts a grandchild from its own image. It waits for the manager's token file and the grandchild before `Stop`, fails instead of tolerating an empty backend list, asserts the manager was alive at marker time, that the manager ended, that every descendant of the backend ended, and that an independent process of the same image and the cohort survive. To make the marker path observable, `CodexRuntimeHost` now logs the code `codex-runtime-stop-requested` (instead of `codex-runtime-timeout`) when the readiness loop ended because the stop marker exists; the test asserts that code. The earlier wording "never becomes ready" is corrected: the 039 stand-in exited immediately, so the branch was not reached.
- ANALYSIS-2701: tray exit registers Claude direct, Codex direct, Codex shared and Codex owned sessions. The owned record points at an in-test `CodexStandInServer` (silent after `initialize`, so the observer is open at exit) with the fixture token. The row waits for `initialize`, requests exit, then asserts the stand-in saw the bearer token and the connection close and received no `thread/resume`, `thread/start`, `thread/archive` or `turn/*`. The update rows register the same four sessions. `CodexStandInServer` gained a `Closed` counter. The update fixture's release contract now declares capture and attachment health and the ingress inventory like a real release, so the gates that protect live sessions run (found because the native rows leave the tray time to evaluate attachment health).
- QA-3401: `CodexLoopbackTransport` sets `Options.Proxy = null` (as `CodexSharedTransport` uses `UseProxy = false`). The runtime-host readiness probe goes through the same transport, so it is fixed by the same change; no other `ClientWebSocket` exists in `src`. Test `TheOwnedConnectionNeverGoesThroughAProxy`: the real runtime host with a live stand-in backend and every proxy variable pointing at a listener; the listener must see no connection while the probe retries.
