## Findings

### QA-1400: QA-1307 is only fixed for `bell-tower launch`; a profile (module) managed Codex launch with an unproven mode still loses its binding

- Severity: warning
- Related task / requirement: 2.2, "profile users must see no change" (QA-1307)
- Location: `src/BellTower/Core/NativeAdoption.cs:35-40,62-68` (provisional capture and `Reconcile`), `src/BellTower/Integration/BellTower.psm1:35-58` (profile launch), `tests/BellTower.Tests/Providers/NativeAdoptionReconcileTests.cs:79-125`
- Expected / actual: a provisional managed capture stays direct only when a stored managed record already has `Process` equal to the hooked agent and live. That record exists only for `AgentLauncher` launches, which save the child process before hooks run. The PowerShell profile launch creates no attachment record (it only sets `BELLTOWER_ATTACHMENT`, calls `prepare-session` and starts the agent), so at the first hook `previous` is null and `Reconcile` returns the shared-runtime form. For Codex any unknown mode (unreadable or protected command line, or an option outside the new known-flag list in `AgentModeClassifier.cs:25-28`, such as an unlisted TUI flag) therefore drops process, host, managed title/background, palette and name for profile users. Before this change the profile's `BELLTOWER_DEDICATED=1` kept such a launch direct. The test fixture only covers the pre-saved launch record, and its "no record" row asserts the fail-closed result as intended behavior, so the profile case is not exercised. The cost of the stricter option list is that more real invocations become unknown, which widens this gap. Claude is unaffected (unknown stays direct).
- Reproduction: source inspection of `Reconcile` with `previous == null` and a provisional capture; the profile flow in `BellTower.psm1` as the source of the missing record. Not executed against an installed profile launch.
- Evidence: source and the test file; the executed tests pass because they do not cover this case.
- Recommended correction: provide an independent proof for the profile flow that does not rely on an inherited flag (for example have `prepare-session` or the first verified registration record the launch before hooks, or accept a provisional capture on first registration when no other managed record names a live different process), and add a profile-shaped test row (managed id, no stored record, unknown mode) for Codex; or record an explicit user decision accepting the fail-closed behavior for profile launches with an unproven mode and list it in the compatibility notes.
- Relationship: residual of QA-1307
