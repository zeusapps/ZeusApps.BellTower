## Findings

### QA-2400: Shim-launched managed Codex backends (npm, script) stay unbound compared with before 2.2

- Severity: warning
- Related task / requirement: 2.2/2.5; ANALYSIS-1502; "existing launch functions and owned runtimes keep working"
- Location: `src/BellTower/Core/NativeAdoption.cs` `Reconcile` (`pending.AgentParent == owned.Manager`); `src/BellTower/Sessions/CodexRuntimeHost.cs` `RunAsync` (npm: `node codex.js app-server`, other: `powershell -EncodedCommand`)
- Expected / actual: before 2.2 any hook with `BELLTOWER_DEDICATED=1` was bound. `CodexRuntimeHost` explicitly supports an npm install and a PowerShell shim, where the hooked `codex.exe` is a grandchild of the manager (manager -> node/powershell -> codex.exe). The proof requires the direct parent to be the manager, so these installs now end shared, with no host, no native name write and no pump lookup. Native-exe installs are restored. The developer lists this as a limit; the test row `node`/`powershell` + valid record pins the shared result.
- Reproduction: `NativeOwnedRuntimeProcessTests` rows with `between` = `node` or `powershell` (both pass because they assert the loss).
- Evidence: real stand-in process rows; `git show 2f1de7f:src/BellTower.Ingress/Program.cs` line 33.
- Recommended correction: orchestrator decision. Either accept it explicitly as a documented regression for shim installs, or extend the proof, still record-based and never by image name, to "the record's manager (PID and creation time, live) is an ancestor of the agent within a small bound". A descendant of the manager cannot be an independent backend, because the manager is not an ancestor of the user's shell. Then add matched rows (npm shape, powershell shape, independent backend under the shell).
- Relationship: residual of ANALYSIS-1502; not a regression of the restored native-exe shape.

No other findings.
