### QA-3600: "not applicable" for Claude shared backend rests on an assertion, and the "verified" wording overstates it

- Severity: warning
- Related task / requirement: 3.4; AGENTS.md parity (exceptions need evidence; "not applicable only where a mode truly does not exist")
- Location: src/BellTower/Diagnostics/CapabilityMatrix.cs (row "Native name and runtime status: Codex shared backend", Claude cell: "Claude Code has no shared backend known to Bell Tower (verified interactive and -p shapes on 2.1.310)"); docs/compatibility.md same row
- Expected / actual: the absence of a Claude shared backend should be backed by primary evidence, or be labelled as a design assumption. Retained evidence only shows Claude `--print` captures (findings.md; native-adoption-002 reports Claude 2.1.312) and launch-shape classification fixtures (implementation-024); implementation-034 itself says "by assumption". No retained check verifies an interactive Claude 2.1.310 session has no shared backend, and the version in the text (2.1.310) differs from the matrix scope (2.1.306). "verified interactive" is stronger than the evidence.
- Reproduction: grep evidence/ for 2.1.310 together with "shared"/"interactive"; only fixtures and classification rows appear
- Evidence: implementation-028 line 14, implementation-034 line 18, implementation-024 lines 21-22, findings.md line 17
- Recommended correction: reword to "no shared backend known to Bell Tower (design assumption; no Claude shared-runtime surface was probed)" and drop "verified interactive"; keep "not applicable" only with that scoping, or mark unverified with closing evidence if parity risk is a concern.
