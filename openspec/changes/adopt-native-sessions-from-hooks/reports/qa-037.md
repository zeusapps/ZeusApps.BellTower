## Failure investigation: ManagementOwnershipProcessTests

- Not a baseline defect and not a deterministic defect of the current tree: the class passes 20/20 on the clean worktree of 0b11026 and 20/20 on the current tree, run alone with the same command. The three variants of `UpdateReplacesOnlyTheTrayAndLeavesEveryOtherProcess` also did not fail in the current-tree full suite.
- Mechanism of the reported error: `CreateInstallation` (`tests/BellTower.Tests/Distribution/ManagementOwnershipProcessTests.cs`, around line 559) copies `src/BellTower.Launcher/bin/<Configuration>/<tfm>` into the fixture install root; `Installation..ctor` then throws `Unsupported installation` when the launcher executable is absent. The fixture therefore depends on the Launcher project's `bin/Release/net10.0-windows` output being present and complete at test time.
- Most likely cause (hypothesis, not reproduced): that output was missing or being rewritten while DEV-042 ran its tests, for example by a concurrent `dotnet build`/`dotnet test` of another role against the same tree, or a build between the Launcher output clean and its rewrite. Current output is complete (`bell-tower.exe`, `.dll`, `.deps.json`, `.runtimeconfig.json`). Also possible: a test run with `--artifacts-path` or a different configuration so that `output.Parent.Name`/`output.Name` did not map to the Launcher bin folder. Neither can be confirmed from the retained evidence.
- Raised as a suggestion (QA-3700) because the fixture's dependence on build layout makes it fragile under concurrent builds.
- The three unnamed DEV-042 full-suite failures are not recoverable; the three failures named above are the ones on the current tree and all passed alone.
