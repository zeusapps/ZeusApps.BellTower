## Findings

### QA-550: `statusline` is missing from the non-tray command list, so every status line process is "unclassifiable"

- Severity: warning
- Related task / requirement: LIVE-001
- Location: src/BellTower/IO/TrayInvocationCommand.cs:16 (revision 84dac98 plus working tree; unchanged by the target)
- Expected / actual: The CLI command is named `statusline` (src/BellTower/Cli/StatusLineCommand.cs:8), but `NonTrayCommands` lists `"status-line"`. `TrayInvocationCommand.Classify` therefore throws "Process command line has an unknown Bell Tower command" for every `bell-tower statusline ...` process (both `--provider claude` and `--provider codex`), so `Get-InstallationTrayScan` reports each as unclassifiable instead of `NotTray`. The new re-scan masks this for processes that end within the deadline, but the root cause of LIVE-001 remains: any status line process alive in the last two scans at the deadline (for example a stalled stdin) makes Switch refuse, and the drain depends on identity churn rather than on correct classification.
- Reproduction: hold a `bell-tower.exe statusline --provider claude --data-dir <data>` open on stdin in a disposable installation and run Switch (case `negative` in [qa-011-native.ps1](../evidence/qa-011-native.ps1)).
- Evidence: the refusal text in both negative results names PID of the `versions\0.1.9008` child with "Process command line has an unknown Bell Tower command".
- Recommended correction: add `statusline` to `NonTrayCommands` (keep or drop `status-line` as an alias), and add a test that every registered CLI command other than `tray` is classified as `NotTray`, so the list cannot drift from the command registry again. Applies to both providers.
- Relationship: related to LIVE-001 (root-cause completeness); not a regression of the target
