## Findings

### QA-300: A Codex fork whose parent's live work is newer than the copied history loses that inherited work when the boundary arrives after the copied prefix

- Severity: suggestion (narrow race, Codex only, unproven in a real fork; recovers at the fork's next work action)
- Related task / requirement: ANALYSIS-200 fix condition; parity policy in AGENTS.md
- Location: `src/BellTower/Sessions/IdentityHistoryReader.cs:232-248` (the `WorkFloorAt is not null || WorkSource starts with "fork:"` condition in `Merge`)
- Expected / actual:
  - Expected: Claude and Codex end the same. The Claude fork keeps the work inherited from its parent's live identity (`fork:Write`, `change-b`) because its copied records keep old stamps and are not newer.
  - Actual (Codex): when a tick reads the copied prefix before the fork's own boundary event, the restamped copies are newer than the inherited work and replace it (`change-b/fork:Write` becomes `change-a/history:edit`). The source is then `history:*`, so when the boundary arrives the condition is false, nothing is excluded or retracted, and the older copied work stays until the fork's own work. In the same-data case with the boundary visible on first read, Codex keeps `change-b` (the condition holds). So the outcome depends on read timing, and the shape differs from Claude.
- Reproduction: `qa-005-probe-fork.ps1.txt -Provider codex -Case growth -Mode livedif -Bin <Release dir>` (and `growth-large`); compare `-Provider claude`. Copy the script outside the repo and pass `-Bin src/BellTower/bin/Release/net10.0-windows`.
- Evidence: [qa-005-probe-summary.txt](../evidence/qa-005-probe-summary.txt), section livedif: Claude growth: `change-b/fork:Write` at every tick; Codex growth: `prefix only` tick `change-a/history:edit`, unchanged after `boundary appended`. Codex small keeps `change-b/fork:Write`.
- Recommended correction: key the condition on persistent inheritance evidence instead of the current `WorkSource` (for example `ForkInheritedFrom` set, or a stored flag that the fork's work came from the parent), so the exclusion and the QA-250 retraction also apply after the inherited work was replaced by restamped copies. Keep ANALYSIS-200 intact: orphan and unread-parent forks (no inheritance) must still use their copied work. Add a growth test with a parent whose live work differs from the copied history, for both clients.
- Relationship: residual of the ANALYSIS-200 fix condition (the developer's `fork:*` addition); same race class as QA-250.
