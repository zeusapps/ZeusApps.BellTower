## Findings

### QA-150: Branch invalidation before the first history read leaves the pre-switch work re-selectable

- Severity: warning
- Related task / requirement: 3.3; QA-004 / ANALYSIS-001
- Location: `src/BellTower/Core/WorkPolicy.cs:76-81` (`Clear` with `WorkClear.Branch` sets `HistoryFloor = Math.Max(HistoryFloor, HistoryLength)`), `src/BellTower/Core/WorkPolicy.cs:17` (floor test)
- Expected / actual: Expected: after a same-checkout branch change, work recorded before the switch is not recovered from history again, whenever the history is first read. Actual: when `HistoryLength` is still 0 (live hook work exists, history not yet read) the floor becomes 0, `Apply` excludes nothing, and the first history pass re-selects the pre-switch change as active work on the new branch.
- Reproduction: Probe `LiveWorkThenBranchSwitchBeforeFirstHistoryRead` for `claude` and `codex` (source in [qa-002-probes.cs.txt](../evidence/qa-002-probes.cs.txt)).
- Evidence: [qa-002-probe-results.txt](../evidence/qa-002-probe-results.txt): both clients `after switch ActiveWork=null floor=0 len=0`, then `after first history read ActiveWork=change-a source=history:edit`. The developer acknowledged this window; it is not limited to one tick when a transcript path is bound late or the reader has not run (for example after tray start or while history is unreadable), and it is the same visible defect as QA-004, so task 3.3 is not fully met.
- Recommended correction: Record "floor pending" when the invalidation happens with no history read (`HistoryFingerprint` unset or length 0) and have the first history pass set the floor to the current end of file (or the file length at invalidation time when known); add a test for both clients.
- Relationship: residual of QA-004 / ANALYSIS-001.
