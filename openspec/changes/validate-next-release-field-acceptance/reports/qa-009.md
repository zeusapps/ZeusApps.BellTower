## Detailed assessment of the assigned questions

### 1. Task 2.2 (Claude Code, Codex, mixed)

- Non-vacuous parts: palette controls are asserted against the product's own palette outputs (a named pin gives exactly `Palette.FromColor("blue").Accent`, a hex pin gives that hex, random and reset clear the pin and land on a different series color, automatic accents pairwise distinct). Names are literal expected strings per role; they would fail on any precedence regression. Resume asserts identical fingerprints (name, accent, pins, association, badge, tab, chip inputs, speech) and an unchanged list. Branch change asserts the automatic association is cleared and the floor recorded, explicit state kept, untouched conversations unchanged, and no resurrection after a second resume plus an 8 s history pass. The badge is the real installed `statusline` command.
- Modeled, not executed natively: the transcripts with the historical work, the Claude `custom-title` record, and the `PostToolUse` inspection payloads (no native capture exists). The notes say so. Not performed: real terminal tab write, chip rendering, spoken audio.
- The "role" conversation is the "work" conversation with `--role` (deprecated, ignored by `src/BellTower/Cli/RenameCommand.cs`): it proves role-free naming only, as the scenario states.
- Weak or tautological parts and a self-exempting check are findings QA-162 and QA-164.
- **Codex explicit native names (confirmed from code).** `SessionIdentity.NativeTitle` is assigned only in `src/BellTower/Sessions/IdentityHistoryReader.cs` (`Merge`, line 227) from Claude `custom-title` transcript records (`NativeTitleSource = HistoryState.ClaudeTitleSource`); `Satisfied` requires the title cursor for Claude only. For Codex, `CodexNameService` (line 59) calls `NativeNamePolicy.Pause`, which turns synchronization off and records "paused: native chat name was set outside Bell Tower", and the comment says the name is "not promoted to NativeTitle" because user-versus-generated "is not verified from a primary source". No Codex path writes `NativeTitle` anywhere in `src/`. The developer's claim is correct. Under the AGENTS.md parity rule this is an unfinished parity gap, not a proven restriction: the stated reason is missing verification, which the rule defines as unfinished work. Claude adopts a user `/rename` as the explicit tier; Codex does not, and after a Codex native rename Bell Tower's name and the provider thread name diverge. See QA-161.

### 2. Task 2.3

- Requirements as the task states them: at least 100 hooks per provider (121, 121 and 120 mixed: met); durable within 3 s (met in all runs, max about 0.43 s Codex); median/p95/p99/max reported for round trip, in-agent and durable (met); exact counts (met, accepted equals durable equals delivered). **Median below 300 ms: not met for Codex in 5 of 6 standalone runs (this QA 3, developer 2) and met only inside `--scenario all` (288.1 and 283.9 ms).** Claude (126 to 148 ms) and mixed (175 to 200 ms) always pass.
- The measured interval includes shell startup the product cannot control. The Codex hook command is `& '<ingress>' --provider codex ...` run through `pwsh -NoProfile -NonInteractive -Command` as a child of the fake `codex.exe`; the interval starts when the fake agent receives the request and ends when `pwsh` exits, so it covers pwsh process start, runtime initialization and the ingress. The same-shell `echo 1` control costs 511 to 553 ms, more than the whole hook (364 to 394 ms), so the baseline-adjusted added runtime is negative (about -123 to -158 ms) and the raw median is dominated by pwsh startup. Claude's control (about 101 to 110 ms) gives a sensible added cost of about 38 ms.
- The standing contract measures something else. `openspec/specs/standalone-setup/spec.md` (Baseline-adjusted hook runtime comparison) applies the 300 ms threshold to the difference of means against the `echo 1` control and says historical raw-median results are not to be relabeled; `docs/hook-ingress.md` records the Codex raw median at 385 ms (2026-10-27) and 480 ms in trial 002, explicitly as exceeding 300 ms in the raw-median form. The 2.3 gate is therefore the stricter raw form that the repository has already shown fails on this machine for Codex by pwsh startup alone. See QA-160.
- Percentile method: identical to Ingress.Bench (nearest rank, `ceil(q*n)-1`), same first serial sample, same eight-way batches with alternating legs; the harness also feeds NaN-free durable samples only for matched hooks and requires all hooks matched.
- Matching and non-vacuity: durable completion is the capture file's first appearance in the inbox (watcher plus an 8 ms poll), matched to the hook by session, nth-hook-to-nth-capture order and an ingress time inside the hook window; an unmatched, lost or reordered capture fails the durable and count checks. Delivery is read from the tray's own applied session journals. Rejections, unknown writers and watcher errors must all be zero.
- Bench output contract: no source change to field names, console lines or exit codes. Not confirmed by execution (QA-165).
