## Assessment and limitations

- Acceptance for the four rechecked findings is met on the executed checks. The decisions in `reports/findings.md` are respected: the ANALYSIS-100 product option stays deferred, the folder option for 101 is dismissed, and task 4.4 states the required setup rerun.
- Limit: the cancel and exit handlers were reviewed from source only. Residual gap seen in source, not a finding: if an interrupt arrives after `cleanup.Run()` has already run in the `finally` block but before `Finish` writes the result, `Abort` skips (the cleanup flag is set). The process then exits without `result.json`. The window is the production comparison only. The next run's sweep does not depend on that file, so nothing is left behind. Raising it is at the orchestrator's discretion.
- Limit: the task-route failure of the hook-started-tray check was verified from source, not provoked in a run.
- Limit: the Codex shell order was checked against the harness's own tests and the archived 0.164.0 evidence, not by running real Codex.
- Limit: the sweep assumes no other harness run is active, as documented. I ran only one harness at a time. One earlier hidden run was killed almost immediately while it still saw only the production task; it left nothing under `runs\` and the later runs removed nothing further.
- Writes: only this report and ignored output under `artifacts/qa-007/` and `artifacts/field-acceptance/runs/`. The production task, tray, installation, data, `~/.claude` and `~/.codex` were not touched. I killed only processes in the harness run tree.
