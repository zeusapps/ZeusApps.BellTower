## How to read this ledger

- Archive path prefix `A:` means `openspec/changes/archive/`.
- Status values: `implemented-with-evidence` (source and tests present, archived implementation or review records, no live check required beyond what is named), `fixture-only` (source and fixtures exist, no user-controlled or installed-package observation yet), `live-check-outstanding` (a named user-controlled or installed check is still required), `cancelled` (removed by user decision; not passed and not deferred).
- "Verified by DEV-001" means the named source and test files exist at the baseline and, where stated, the named tests ran green in this session. Everything else is taken from the archived task lists, evidence and reports and is labeled as recorded evidence. Historical results hold only for their recorded version and mode.
- Provider coverage is stated per row as C (Claude Code), X (Codex) and M (mixed simultaneous sessions): `fixture` means matched automated fixtures, `live` means a user-controlled observation recorded in the archive, `none` means no evidence found (an open gap, not a restriction). No row relies on a hard provider restriction.
- "Shipped in" (the release whose tag contains the implementation) is separate from "archived" (the date the OpenSpec change was archived); they differ. Shipping was checked with `git cat-file -e v0.1.9:<path>` and commit ancestry against the tags.
- Fixtures are not authenticated provider acceptance. Live user checks recorded in the archive are separate from fixtures and are preserved here, not repeated.
