## Findings

### QA-001: Codex per-assignment model override is shadowed by role defaults

- Severity: warning
- Related task / requirement: task 1.2; `Per-role model selection`, scenario “Orchestrator raises an assignment's model”
- Location: `.codex/agents/developer.toml:4`, `.codex/agents/qa.toml:4`, `.codex/agents/code-analyzer.toml:4-5`; `.agents/workflows/openspec-delegation.md:71`; `docs/agent-workflow.md:28`
- Expected / actual: The workflow says the orchestrator can pass a per-invocation model setting for an assignment. Current Codex documentation says `model` and `model_reasoning_effort` in a custom-agent file take precedence over spawn values. All three Codex roles set these fields, so the documented per-invocation override cannot change the selected model/effort for those roles.
- Reproduction: Inspect the three role files and compare them with “Choosing models and reasoning” / “Custom agent file schema” in the linked Codex subagents documentation.
- Evidence: Current primary documentation states custom-agent file values take precedence after spawn/default/parent resolution. Source lines listed above record both the role defaults and the shared override instruction.
- Recommended correction: Adjust Codex's override procedure to a supported mechanism that preserves role defaults, or document this client-specific limitation and a supported alternative. Do not record a Codex override as successful without an execution check.
- Relationship: none
