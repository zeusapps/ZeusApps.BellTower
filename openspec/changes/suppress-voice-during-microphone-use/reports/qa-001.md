## Findings

### QA-001: Incorrect audio endpoint collection IID prevents a valid detector scan

- Severity: critical
- Related task / requirement: 1.3; current-session microphone state
- Location: `src/BellTower/Tray/WindowsMicrophoneActivitySource.cs:289`
- Expected / actual: `EnumAudioEndpoints` should marshal the returned collection using the Windows `IMMDeviceCollection` interface identity. The source declares a different GUID. The COM collection cannot be reliably marshaled as that interface; failures are caught and converted to Unknown, so enabled suppression can remain tone-only instead of obtaining fresh state. Code-analyzer finding ANALYSIS-001 independently records the SDK IID comparison.
- Reproduction: Compare the `[Guid]` on the declared `IMMDeviceCollection` with the Windows SDK interface IID, then follow `EnumAudioEndpoints(..., out endpoints)` at line 132. No native reproduction was attempted because the other ABI errors make that unsafe.
- Evidence: Source inspection at the reviewed identity; Microsoft documents that `IMMDeviceEnumerator::EnumAudioEndpoints` returns an `IMMDeviceCollection` [interface](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nn-mmdeviceapi-immdevicecollection).
- Recommended correction: Declare the exact SDK IID and cover identity/constants through a narrow deterministic contract test, then safely probe Windows without opening an audio stream.
- Relationship: Duplicate of ANALYSIS-001 pending ledger triage.

### QA-002: `IAudioSessionManager2` vtable declaration calls the wrong native slots

- Severity: critical
- Related task / requirement: 1.3; current-session microphone state
- Location: `src/BellTower/Tray/WindowsMicrophoneActivitySource.cs:311`
- Expected / actual: The managed vtable order must match the inherited `IAudioSessionManager` slots followed by `GetSessionEnumerator`, `RegisterSessionNotification`, and subsequent `IAudioSessionManager2` methods. The source declares Register/Unregister before GetSessionEnumerator. Calls at lines 156 and 158 therefore dispatch to different native methods with incompatible signatures. This may fail, corrupt the observation, or destabilize a caller. Code-analyzer finding ANALYSIS-002 independently records this ABI mismatch.
- Reproduction: Compare the declared interface order with the Microsoft `IAudioSessionManager2` inheritance and method contract, then follow calls at lines 156–158. Native invocation was intentionally stopped before executing this vtable.
- Evidence: Source inspection at the reviewed identity; Microsoft documents that `IAudioSessionManager2` inherits `IAudioSessionManager` and exposes the session enumerator and notification methods [here](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nn-audiopolicy-iaudiosessionmanager2). Its registration contract also requires initialization via enumeration [here](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessionmanager2-registersessionnotification).
- Recommended correction: Correct the full inherited slot order and verify every method signature against the Windows SDK before any native probe.
- Relationship: Duplicate of ANALYSIS-002 pending ledger triage.

### QA-003: Native active and inactive state values are reversed

- Severity: critical
- Related task / requirement: 1.3; Desktop call uses microphone
- Location: `src/BellTower/Tray/WindowsMicrophoneActivitySource.cs:274`
- Expected / actual: Windows defines `AudioSessionStateInactive` first (value 0) and `AudioSessionStateActive` second (value 1). The source declares Active first and compares `GetState` with that enum at line 252. An actual active shared-mode microphone session can therefore be recorded as inactive, allowing speech during microphone use. Code-analyzer finding ANALYSIS-003 independently records the enum mismatch.
- Reproduction: Compare the enum to Microsoft’s published [AudioSessionState values](https://learn.microsoft.com/en-us/windows/win32/api/audiosessiontypes/ne-audiosessiontypes-audiosessionstate); inspect `IsActive` at line 252. The production COM path was not run.
- Evidence: Source inspection and the primary enum contract above; fixture reducer tests inject already-translated states, so they do not exercise native numeric values.
- Recommended correction: Match numeric values to the SDK and add a contract test mapping native Active/Inactive values to the policy states.
- Relationship: Duplicate of ANALYSIS-003 pending ledger triage.

### QA-005: No fixture exercises microphone activation after speech begins

- Severity: warning
- Related task / requirement: 2.3; Playback recheck and cancellation
- Location: `tests/BellTower.Tests/Tray/AudioQueueTests.cs:140`
- Expected / actual: Task 2.3 requires rechecking/cancelling remaining speech when microphone activity changes during playback. The existing transition test changes state during the tone and checks that speech is initially cancelled before it begins. It does not flip the fake source after speech starts and assert the sink's polling callback cancels the remaining phrase. Source inspection shows a polling call in the SAPI loop, but that is not an executed functional test.
- Reproduction: Run `MicrophoneActivationAfterToneCancelsSpeechOnly` and inspect the fake sink; it records `speechCancelled()` before entering speech and never polls it after a state transition.
- Evidence: 36-test fixture run; source inspection of the SAPI loop is not a functional observation.
- Recommended correction: Extend the recording sink fixture to begin speech, flip the fake microphone source to Active, poll the cancellation callback, and verify cancellation without physical speech.
- Relationship: None identified.
