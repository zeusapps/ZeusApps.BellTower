Note on the glued case: a closing quote immediately followed by a letter or digit (`'C:\a\My Repo'tail`) is not recognised as a close, so the unquoted rule masks only the first word (`<path> Repo'tail`). The rule cannot tell this from `Bob's Repo`. It needs a message that omits the separator after a closing quote, which .NET IO exceptions and normal message text do not do. Not blocking; recorded as a design limitation, consistent with the DEV-007 rule.
