## Findings

### QA-100: A capture backlog skips compaction, so a save over the budget removes ended sessions that compaction would have kept

- Severity: warning
- Related task / requirement: 1.5; spec scenario "State at the budget recovers" ("the first drain compacts and, if needed, removes the oldest ended sessions"); design decisions 1 and 3
- Location: `src/BellTower/IO/StateStore.cs` line 98 (`var retained = !backlog && CompactSettledSessions(...)`) with the fallback in `src/BellTower/IO/StateSnapshotStore.cs` `Save`
- Expected / actual: When persisted state is at the budget and more than `CaptureConsumer.BatchSize` (128) captures are queued, the first drain should compact settled sessions before removing any. Actual: the backlog skips compaction, the first batch is applied, and if the encoded state is then over the budget the fallback removes whole ended sessions (oldest first) instead. Compaction would have shrunk them to a few kilobytes and kept them. The next drain compacts the rest, so the removed sessions are lost for nothing. The state is still bounded and no live session is lost, so this is bounded data loss, not a wedge. The field failure that motivated the change (a stopped tray with captures piling up) is the case that produces both a large state and a backlog.
- Reproduction: Scratch probe: 40 ended sessions (both providers, full journals) plus one live session persisted, 150 queued captures, budget = written size minus 150000 bytes. Drain 1: `ended=39 live=129 journaled=39 queued=22` (one ended session removed by the fallback, none compacted). Drain 2: `ended=39 journaled=0 queued=0 size=451049`. So the second drain compacts all 39 to 451 KB, which would have fit the budget from the start without removing the session.
- Evidence: probe output above (scratch copy, removed). No test combines a backlog with a tight budget; the tests for the backlog use the default budget and the budget tests use fewer than 129 captures. The inbox clause of `HasBacklog` (more than 2000 inbox files) also has no test (mutant survives).
- Recommended correction: Keep the skip for the normal case, but do not let it cost sessions. For example, compact settled sessions before the fallback removes any (inside the save path, or by compacting when the first encode is over the budget), so a backlog defers compaction only while the state fits. Add a drain-level test with more than 128 queued captures and a budget that the compacted state fits but the uncompacted one does not, and one test with more than 2000 inbox files.
- Relationship: new; refines ANALYSIS-003 (a)

## Assessment and limitations

- The sanitizer, rate limit, record writes, floor, quiet drain, fallback pass bound and the two-step recovery all work as specified and are covered by tests that fail under mutation, for Claude Code and Codex (shared code, no provider branch).
- One defect in the fix: QA-100 (a backlog plus a tight budget loses ended sessions that compaction would keep). The inbox threshold itself is correct, and the deferral cannot last forever because each drain consumes a batch, but until it ends only the removing fallback bounds the state.
- Surviving mutants with no behavior defect: capture clause at exactly one batch, first End versus last End, reason eviction order, and the redundant `Quoted` rule.
- Not performed: the installed check (3.3), the real tray, the real data directory and `TrayApplication` execution. `openspec validate --strict` was not part of this assignment. Deferred findings (ANALYSIS-004, -005, -007, QA-004, QA-005) were not rechecked.
- Unexpected writes: none to the repository. The report is the only file written under the change root. Scratch files were outside the repository.
- Decision needed: whether QA-100 is fixed in this change or accepted as bounded loss in an edge case.
