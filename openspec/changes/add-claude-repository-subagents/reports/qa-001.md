## Findings

### QA-001: Documented `-Paths <paths>` invocation fails or silently returns an empty identity

- Severity: warning
- Related task / requirement: 2.3, 2.6; spec "Durable change-local reports" (identity recorded); design D10
- Location: `scripts/review-identity.ps1` lines 1-5 (parameter block); `.agents/roles/qa.md:26`, `.agents/roles/code-analyzer.md:27`, `.agents/roles/developer.md:31`, `.agents/workflows/openspec-delegation.md:35`, `docs/agent-workflow.md:43` (all document `-Paths <paths>`); `tests/BellTower.Tests/Scripts/ReviewIdentityScriptTests.cs` `Run` method (passes paths positionally)
- Expected / actual: Expected: the invocation shown in every role and the how-to produces the identity for the listed paths. Actual: `[string[]]$Paths` is declared `ValueFromRemainingArguments`, so `-Paths` takes exactly one value, and further space-separated paths raise "A positional parameter cannot be found that accepts argument '.codex/agents'". The comma form `-Paths .claude/agents,AGENTS.md` does not error but treats the value as a single path string, producing `files=0 diff=e3b0c44298fc untracked=0/e3b0c44298fc` (the SHA-256 of empty input). A reviewer who follows the documented form with one path or with commas gets a clean-looking, wrong identity that equals "no changes". Only the undocumented positional form works (this review used it).
- Reproduction: from the repository root, `pwsh -NoProfile -File scripts/review-identity.ps1 -Baseline b3e007e4c38a7893886e908998abbd5dfd5844a3 -Paths .claude/agents .codex/agents` (error), then `... -Paths .claude/agents,AGENTS.md` (summary `files=0`). Also reproduced with `powershell -File` (error). Compare `... -Baseline b3e007e... .claude/agents AGENTS.md` (works).
- Evidence: command outputs above; the existing test passes only because it never uses `-Paths`.
- Recommended correction: make `-Paths` accept the documented form (for example declare `Position`d `[string[]]$Paths` without `ValueFromRemainingArguments` and split a single comma-containing value, or document and use the positional form everywhere) and fail loudly when a path matches nothing or `files=0` unexpectedly. Add a test case that runs the exact documented command line and a case with a non-matching path. Update the five documentation locations to match whatever form is chosen.
- Relationship: none
