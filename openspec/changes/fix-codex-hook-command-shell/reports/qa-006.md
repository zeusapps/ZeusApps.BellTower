## Findings

### QA-250: Codex probe can reject a durable capture if the runner exits before the next poll

- Severity: warning
- Related task / requirement: task 2.1; task 2.2 failure-before-write probe must accept a durable result
- Location: `src/BellTower/Setup/ProviderHookProbe.cs:200` at the reviewed identity
- Expected / actual: once a correctly decoded Codex capture exists, the verifier should accept delivery regardless of whether the short-lived Codex process exits before the next polling iteration. `observed` is currently set only inside `while (!process.HasExited ...)`; if the process writes the capture and exits between polls, the loop ends with `observed == false` and the later guard rejects the valid capture.
- Reproduction: source inspection confirms this exit/poll ordering. The independent analyzer reported a bounded native reproduction with the capture present but `observed` false in 7/8 attempts (canonical `ANALYSIS-250`). This QA run's four isolated native checks passed and did not independently encounter the race.
- Evidence: [implementation source at the reviewed identity](../../../../src/BellTower/Setup/ProviderHookProbe.cs); current native probe command passed 4/4, so the race is intermittent.
- Recommended correction: check for the durable capture after the polling loop and before rejecting a completed runner; retain the existing provider and capture validation.
- Relationship: same issue as canonical `ANALYSIS-250`.

### QA-251: Project-only Codex removal clears global shell ownership metadata

- Severity: warning
- Related task / requirement: task 3.1; preserve unrelated global provider integration and ownership during project-scoped removal
- Location: `src/BellTower/Setup/IntegrationSetup.cs:47` at the reviewed identity
- Expected / actual: removing profiles for one registered project should leave the global Codex hook shell selection metadata intact because global Codex hooks and settings are not removed. The unconditional `remove && selected.Contains("codex")` branch clears `SelectedCodexHookShell` even when `removeProject` is true; the resulting manifest forgets which shell was selected for the still-installed global hook.
- Reproduction: source inspection confirms `removeProject` skips provider settings edits at lines 65-66 while the earlier metadata-clearing branch still runs. The independent analyzer's read-only plan reproduction observed zero provider settings changes and `SelectedCodexHookShell` changing from `Cmd` to null (canonical `ANALYSIS-251`).
- Evidence: [IntegrationSetup.cs](../../../../src/BellTower/Setup/IntegrationSetup.cs); isolated plan result reported by the analyzer.
- Recommended correction: clear global shell ownership only for a full Codex integration removal, not a project-only removal.
- Relationship: same issue as canonical `ANALYSIS-251`.
