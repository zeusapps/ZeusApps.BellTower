# Durable hook ingress

The packaged Windows x64 integration uses `bell-tower-ingress.exe`, a roughly 3 MB NativeAOT executable. Both providers use this capture path. It reads bounded JSON, captures process and launch evidence, writes one durable envelope, returns `{}` and exits. Git queries, identity writes, selection effects and shared state locks run in the consumer. Capturing does not start the tray, launcher, desktop application or a provider.

Development executables retain the legacy normalized `event` command for component checks and old helpers. A versioned installation requires a verified native helper before fast setup can proceed; packaging fails if native publication fails.

## Capture-v1 contract

`BellTower.Protocol` owns the shared DTOs, parser, validation, source-generated serializer and atomic spool. It targets net10.0 without Windows Desktop references. Native process inspection is linked separately into the Windows ingress executable.

| Field | Meaning |
| --- | --- |
| `protocol` | Exactly 1; incompatible versions are rejected |
| `id` | Unique N-format GUID, also used as the normalized observation ID |
| `ingressAt` | Capture start in UTC, independent of consumer processing time |
| `observation` | Provider, native session/turn/tool IDs, registration source, event kind, directory, argument fingerprint, main/subagent distinction and bounded background task IDs/types |
| `observation.humanPrompt`, `questionTool`, `providerDelay`, `permissionMode` | Additive human-wait evidence set by the provider adapter: a human-prompt notification (Claude `permission_prompt`) with its credited provider delay, a question-tool observation (`AskUserQuestion`, `request_user_input[_async]`), and the reported permission mode (diagnostics only). Shared reducer policy decides what they mean; an older consumer ignores them and keeps its former timing behavior, and the event kind stays `Permission` so no new kind is introduced |
| `observation.at` | Eligible hook-shell creation time, otherwise ingress time |
| `observation.hookShellStartedAt`, `orderConfidence` | Available ordering evidence; `hook-shell` or `ingress-only`, never an invented provider timestamp |
| `observation.processedAt` | Added by the consumer; never used as event source order |
| `attachment`, `hookShell`, `ancestors` | Available process identities with PID and creation ticks; host and approved presentation ownership flags |
| `dedicated`, `name`, `change` (legacy `role` is read and ignored) | Approved launch metadata; shared/remote Codex keeps its deliberately unverified attachment policy |
| `transcriptPath` | Location only; capture never reads or stores transcript contents |
| `selection`, `selectionRoot`, `selectionPre`, `createdScaffold` | Bounded derived selection evidence; local scaffold confirmation is deferred |

Input is at most 1 MiB of strict UTF-8, allowing a UTF-8 BOM. Envelope output is at most 128 KiB, with at most 32 ancestors and 128 background tasks; JSON depth is 32. Session/attachment IDs are at most 200 characters, tool/turn IDs 256, and paths 32768. Tool arguments enter only a SHA-256 fingerprint or an accepted bounded selection candidate. Commands, tool responses, prompts, assistant messages and credentials, including BELLTOWER_CODEX_TOKEN, are excluded.

The only executable probe is `--protocol-info`. It returns `{"protocol":1,"minimumConsumer":1,"maximumConsumer":1}` and writes no data. Envelope and observation extension fields survive supported round trips. Shared identity, session, attachment and integration ownership records retain their declared extension fields.

## Durability and bounded replay

The helper writes a unique temporary file with write-through and flushes it before an atomic rename into `captures-v1/<utc-ticks>-<id>.json`. Failed writes clean up their temporary file. Rejection diagnostics use one bounded timestamp slot per sanitized category, without shared capture locks or exception messages.

The consumer takes at most 128 captures per drain. The legacy normalized inbox remains readable alongside it. Valid receipt identities are saved with state before deleting their files; unfinished commits leave valid captures for retry. Capture receipt retention checks the known receipt filenames without enumerating an entire capture backlog. Invalid payloads are discarded with a sanitized category; IO/access failures retain valid captures for retry.

Session replay keeps 256 ordered observations and a committed checkpoint per conversation. Ordering uses the captured event time, event kind and envelope ID. Older evidence behind the committed floor is stale and cannot reopen state. An ended capture attachment requires a newer explicit resume registration to reopen; delayed startup/unknown registrations cannot reopen it. Selection retains 128 compact derived evidence records; both legacy and capture adapters use the same selection policy. Successful unpaired results can select, while known newer starts suppress an older completion. No raw tool payload is retained in these journals. Snapshot writes enforce the existing 16 MiB read budget and retain pending captures if that budget is exceeded.

Process-clock evidence does not reconstruct arbitrary source ordering when the provider supplies none. Diagnostics and envelopes retain this uncertainty. Tests shuffle fixed source-evidence fixtures, including results before starts, old registrations after ends, and mixed providers. Viewed/acknowledged episode IDs and manual naming/palette overrides remain stable.

## Setup, migration and compatibility

Human-wait confirmation state is additive in the tray snapshot: each wait may carry `confirmation`, `confirmedAt`, `confirmationCredit` and `ambiguous`, sessions carry bounded `resolvedApprovals` receipts and `promptObserved`, observations carry the additive `humanPrompt`, `questionTool`, `providerDelay`, `permissionMode`, `adapterRevision`, `runtimeApproval`, `runtimeApprovalScope`, `runtimeApprovalRevision` and `restoredSince` fields (capture protocol stays version 1; a missing `adapterRevision` marks a cached ingress image older than these fields, whose legacy `permission_prompt` shape is re-derived by the consumer and reported by doctor as needing a setup refresh). `runtimeApprovalScope` is an opaque set of wait identities and current unresolved candidate membership captured when the Codex runtime query starts; candidate membership is canonicalized and hashed without exposing operation metadata. `runtimeApprovalRevision` changes only when that complete permission-wait scope set changes. The reducer discards positive results when either scope or revision differs, including partial narrowing and an A→A+B→A transition, while unrelated events do not invalidate the result. Older queued runtime observations missing scope or revision, or carrying an obsolete episode-only scope, cannot confirm a wait. Unknown wait fields are preserved on a round trip. Snapshots written before this state read as unverified permission waits (never newly confirmed or announced). A pre-confirmation tray that rewrites the snapshot drops the per-wait confirmation fields, so waits it re-saves are unverified again when a current tray reads them; rolling back therefore loses only confirmed state, not episodes, viewed or dismissed receipts.

Setup verifies the helper against the selected payload inventory and provisions immutable bytes at `integrations/provider-ingress/1/<sha256>/bell-tower-ingress.exe` under the chosen data directory. It probes command forms through Codex's native SessionStart runner with isolated `CODEX_HOME`, disposable data and a loopback fake Responses endpoint, selecting and recording only a form that produces a durable capture. Apply then probes the exact retained helper path with the selected form before changing provider settings. A missing shell, failed command or absent capture aborts setup without changing provider settings. Existing images are retained for cached hooks. Claude continues to use Bash quoting; Claude Code 2.1.310's native CLI delivered a capture through configured Git Bash, and the `CLAUDE_CODE_GIT_BASH_PATH` override is respected during verification. Codex 0.164.0 inherits the shell selected for its turn: its generated PowerShell call form delivered in two tested PowerShell 7 environments, and its generated Cmd form delivered a validated protocol-1 SessionStart capture when both PowerShell directories were denied in process-local MXC and `PATH` was limited to System32. The capture's `HookShell` identity matched its `cmd.exe` ancestor; helper and data paths included spaces, an apostrophe, Unicode, `%NAME%`, and `! & ^ ()` ([native evidence](../openspec/changes/archive/2026-10-28-fix-codex-hook-command-shell/evidence/native-investigation-009.md)). Version-pinned source shows that the normal local Windows 0.164.0 resolver selects PowerShell or its cmd fallback, with no Bash selection branch; external-host Bash and other versions/path-priority combinations remain unverified ([source review](../openspec/changes/archive/2026-10-28-fix-codex-hook-command-shell/evidence/analysis-008-source-checks.md)). The tested command-array config form was rejected by Codex's parser. Doctor repeats the isolated native shell check and reports drift from the recorded selection.

Async is enabled for regular capture hooks. SessionEnd uses fast synchronous capture for both providers. Native provider timeout/cancellation behavior remains outside Bell Tower's ownership; async does not establish durability or latency by itself.

Ownership compares the full handler and group metadata. Ordinary setup retains edited handlers and offers `--migrate-edited-hooks`. Preview shows old/new handlers; adding `--apply` writes backups and replaces edited owned entries explicitly. Unrelated handlers remain. Migration can be repeated without duplicates.

`release.json` advertises `capture: 1`; absent means legacy-only. `capture-protocol.json` records enabled capture. Setup refuses to enable fast hooks under a running tray without a capture-v1 readiness receipt. The current launcher and updater reject incompatible tray selection/rollback while preserving legacy normalized event writers. Compatible rollback means another capture-v1 consumer, not an arbitrary old desktop executable. An old bootstrap that predates this guard cannot enforce it for manual pointer edits; do not use manual edits to select a legacy consumer after fast hooks are enabled.

Doctor reports capped backlog counts, oldest pending age, latest consumption lag, sanitized rejection categories and unverified active process attachments. Its `hookDelivery` object reports configured owned hooks, last observed delivery and `unverified` when settings are configured but no capture has been observed. For a legacy quoted Codex command confirmed by `integration.json` ownership, it also reports `knownBrokenOwnedCommandCount` and the preview command `setup --clients codex --migrate-edited-hooks`; inspect the preview, then add `--apply` to write backups and migrate. Hook text and settings paths are not included. `doctor --transcript <file> --transcript-provider claude` optionally scans at most 1 MiB, 2000 complete lines and 64 KiB per line. The verified shape is `type: attachment`, `attachment.type: hook_cancelled`, boolean `timedOut`, positive integer `timeoutMs` and a record timestamp. It reports only counts and time bounds. Private content, commands and exception messages are excluded. Codex 0.164.0 local exec/terminal transcripts do not retain the tested SessionStart timeout status; the reader reports complete counts unavailable and uses capture health/native status. Other version/mode pairs remain unverified. This restriction applies only to retrospective transcript counts, with [exact proof and regression coverage](../openspec/changes/archive/2026-10-23-speed-up-claude-hook-ingestion/evidence/provider-timeout-probes.md).

## Build and evidence

Package builds require PowerShell 7, .NET 10 and the Windows MSVC/SDK NativeAOT prerequisites. The desktop shell integration still supports Windows PowerShell 5.1. Run `pwsh -File scripts/package.ps1`, then the isolated `tools/BellTower.Ingress.Bench` against that package. It validates generated commands, neutral output, durable counts, latency and crash replay; errors produce a nonzero result rather than an unhandled Windows dialog.

On 2026-10-23, 121 native captures per provider ran at concurrency eight with spaces/apostrophes/Unicode in the selected data path. The first valid run persisted all 242 native captures and 50 legacy controls and restored eight independent sessions. Native Claude median/p95/p99/max: 115.12/131.37/139.80/140.63 ms. Native Codex: 83.19/89.44/102.40/111.53 ms. Legacy-chain median: 1535.03 ms Claude and 1502.01 ms Codex (25 samples each). Every native sample finished below three seconds. These are local generated-shell trials, not authenticated hooks or a reproduction of the field machine's reported timeout rate. The first capture occurs after the provisioning probe; no OS file-cache reset is claimed.

Follow-up package probe (2026-10-27, 0.1.9013): the corrected provider-shell benchmark ran 120 samples at concurrency eight and measured Claude native ingress at 142 ms median (156 ms p95, 176 ms max). Codex PowerShell no-op startup was 344 ms median; the direct helper command was 385 ms median (492 ms p95, 596 ms max), with 0 failed commands and 121 durable Codex captures including the cold sample. Under the raw-median comparison used for that historical run, Codex exceeded the 300 ms threshold. That trial stopped before state-drain/crash-replay; its result remains a raw-latency record and is not recalculated as an adjusted mean.

User-requested adjusted-mean trial 001 (2026-10-27, reviewed package 0.1.9015): for each provider the benchmark ran one serial sample plus 120 samples at concurrency eight for both native ingress and an input-draining shell command ending in `echo 1`. It alternated matched eight-sample batches. The arithmetic-mean estimate was 95.301 ms for Claude and -72.094 ms for Codex. Those numbers are preserved in `artifacts/codex-hook-shell/mean-20261027-01/latency-report.json`, but this baseline variant consumed stdin before echoing and is superseded for the literal-baseline request by trial 002 below.

User-requested adjusted-mean trial 002 (2026-10-27, reviewed package 0.1.9015): the baseline command was exactly `echo 1` in both provider shells; hook and baseline shared shell arguments, environment and synthetic stdin plumbing. Each provider had 121 baseline and 121 hook samples (one serial first sample plus 120 at concurrency eight), with matched eight-sample batches alternating baseline-first and hook-first. Arithmetic mean(native full-hook elapsed) minus arithmetic mean(bare `echo 1` elapsed) was 86.283 ms for Claude (204.911 minus 118.628) and -49.646 ms for Codex (481.118 minus 530.764). Raw native median/p95/p99/max was 203.978/245.120/252.789/254.614 ms for Claude and 479.954/547.921/580.519/587.865 ms for Codex. Both estimates were below 300 ms; no samples failed or reached three seconds. All 242 native captures and 50 legacy events were durable, eight sessions drained, and committed-capture replay passed. The negative Codex estimate is retained as observed and does not imply negative helper cost. [Independent QA](../openspec/changes/archive/2026-10-28-fix-codex-hook-command-shell/reports/qa-005.md) and [analysis](../openspec/changes/archive/2026-10-28-fix-codex-hook-command-shell/reports/analysis-005.md) verified the arithmetic and guards. This synthetic benchmark is not authenticated native-provider or user acceptance. Per-sample timings are in ignored `artifacts/codex-hook-shell/mean-20261027-02/latency-report.json`.
