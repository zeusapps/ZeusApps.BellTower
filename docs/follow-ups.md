## Bounded monitoring state (`bound-ended-session-state`)

Deferred suggestions and accepted residuals from the review of this change (see its `reports/findings.md`):

- A refused over-budget save re-encodes the whole state on each tick and mutates its input (ANALYSIS-004). Doctor's `state` section decodes the state file once more without the store lock (ANALYSIS-005). The oldest-ended ordering is duplicated and the removal policy is split across the store and the snapshot store (ANALYSIS-007). The doctor and tray refresh-health wiring has no direct test (QA-004).
- Draining a backlog costs about 4 s per batch of 128 captures on the maintainer's real data, because each accepted capture replays the live sessions' 256-event causal journals. This is existing reducer cost, outside this change.
- Refresh-reason sanitizing masks every rooted path in realistic .NET IO messages. Accepted residuals with no known producer in the refresh path: an unquoted path whose final name contains a space keeps the words after the space; a quoted segment without a drive, UNC, Unix, profile or data-directory root is not masked; a closing quote glued to a letter or digit keeps the final word; and when no valid closing quote follows on the line (for example a path cut at the 2,000-character cap), text after an apostrophe before a separator is kept.

## Native sessions adopted from hooks (`adopt-native-sessions-from-hooks`)

Deferred suggestions from the final review of this change (see its `reports/analysis-058.md`, `reports/analysis-051.md` onward and `reports/findings.md`). Each applies to both providers unless stated.

- Automatic ingress re-provision on update and development switch (ANALYSIS-5800(b)). Setup is the only step that copies the ingress image and rewrites the owned hook commands, so an update or a dev switch leaves the hooks on the older image until setup is run again; doctor now reports this read-only (`hookStart.ingressImage`). Refreshing the image automatically needs a user decision, because changed Codex hook commands may need to be trusted again.
- Transcript fallback after a refused shared read (ANALYSIS-5802). When the shared Codex backend refuses a read for a plain default session, the transcript reviewer signal that `codex --no-daemon` sessions use is no longer tried. A probe of what the refusal and the transcript show comes first.
- Per-session negative cache and log-once for shared permission reads (ANALYSIS-5803, ANALYSIS-2405). A waiting shared-backend conversation opens one shared read per second and logs each refusal; a bounded negative cache per session and a single log line would bound the cost.
- Hook-to-color latency of about 4 s for native sessions, both providers. Title and color appear about 4 s after the first accepted hook (measured for Claude Code and `codex --no-daemon`); a cause and a shorter path are not investigated.
- A typed reason for a permanent limit (ANALYSIS-5100). `NavigationReasons.IsPermanentLimit` recognizes the shared-backend limit by comparing the result message with a constant; the only producer builds it in process, so this is not yet a defect, but a typed reason becomes warranted when a second permanent limit or a result that crosses a process boundary appears.
- A direct Claude status-line command without PowerShell (ANALYSIS-5401). Every status-line render starts Windows PowerShell (about 0.5 s measured) before the launcher; a direct quoted launcher command like the Claude event hook would cut that and make cancelled renders rarer. It does not replace the ANALYSIS-5400 guard.
- Tests that start a detached tray can leave it running after the workspace is deleted (ANALYSIS-6000, duplicate QA-6501). `PrelaunchPresentationTests.ColorPrecedesTheNativeAgentAndItsFirstHookUsesTheSamePalette`, `PowerShellModuleTests.SessionFunctionsLaunchNativeChildrenAndRestoreShellEnvironment`, `CliTests.LaunchForwardsAgentArgumentsAndKeepsOwnMetadataSeparate` and `CliTests.DetachedTraySurvivesStartingProcessAndManagementIsScoped` run `tray --data-dir <root> --silent` detached, and their `finally` blocks check or wait for the exit with a single check or an already expired deadline, so `TestWorkspace.Dispose` can delete the workspace while the tray still runs. The leaked tray runs indefinitely, locks `src/BellTower/bin/Release` (it blocked the in-tree build in DEV-069) and can skew later process-sensitive tests; no user data is at risk. Proposed: a shared `TestWorkspace.StopTray` helper that matches only that workspace's exact `--data-dir`, requests the exit again if `exit.request` disappears, waits with its own deadline and kills only the matching processes as a last resort, never by process name. Optionally a test-only no-tray path (a product change) or pre-holding the workspace's `tray-instance` mutex, and a product rule that a tray exits when its data root disappears; each of these needs a decision. `DetachedTraySurvives...` must still prove the tray outlives the starting process before cleanup. It applies to both providers' launch paths.
